## Array creation is O(1) in the number of chunks

<!--
HIGHLIGHT 2. Continues the "going faster" thread the 3.3.0 post promised.

Relevant issues and pull requests:
- #4174 -- the report (array creation and coordinate selection allocated
  per-chunk arrays)
- #4218 -- the fix: chunk normalization returns a `ChunkGrid` whose uniform
  dimensions are a size + extent pair (`FixedDimension`) instead of one entry
  per chunk; the intermediate `ChunksTuple` representation is gone.

Before/after that writes itself (verified):

    import zarr
    # 3.3.0: ValueError ("array is too big") or, for chunks=(1, 1) on a
    # (2**31, 2**31) array, ~17 GB allocated per dimension.
    # 3.4.0: instant.
    z = zarr.create_array({}, shape=(2**62,), chunks=(1,), dtype="int32")
    print(z.nchunks)

Note the coordinate-selection half of #4174 is still open (#4172 fixed sorted

## Rectilinear chunk grids grew up (still experimental)

<!--
HIGHLIGHT 3. 3.3.0 introduced rectilinear (variable-size) chunks (#3802,
#3899); 3.4.0 makes them behave. Keep the "experimental, opt in with
zarr.config.set({"array.rectilinear_chunks": True})" caveat prominent, and
mirror the 3.3.0 post's "How to use it" subsection.

What changed (all in #4218 / #4272, plus #4307 / #4328 for zero-length axes):

- Grid kind follows input syntax: a nested per-dimension list ALWAYS requests a
  rectilinear grid, even when the edges happen to be uniform. 3.3.0 silently
  collapsed uniform-plus-short-tail lists to a regular grid, which changed
  resize semantics -- the append-only time-series use case from #4272:

      zarr.config.set({"array.rectilinear_chunks": True})
      edges = [168] * 13 + [24]           # coarse backfill then a partial window
      z = zarr.create_array(store, shape=(sum(edges),), chunks=[edges], dtype="f4")
      z.append(np.zeros(24, dtype="f4"))   # appends a new edge chunk;
      print(z.write_chunk_sizes)           # a regular grid would have rewritten the tail

  CONSEQUENCE TO STATE PLAINLY (it is the one user-visible change for people
  who never enable the flag): `chunks=((4,), (4,))` / `[[3, 3, 1]]` -- the
  shape of a dask array's `.chunks` -- is no longer quietly accepted as a
  regular grid when the flag is off. It raises, exactly as 3.2.x did; the
  silent acceptance existed only in 3.3.0. Use one int per dimension, or a dask
  array's `.chunksize`.

- `zarr.from_array(..., chunks="keep")` reproduces a rectilinear source grid
  exactly (in O(ndim)); sharding under a rectilinear shard grid is preserved
  instead of dropped.
- `Array.chunks` is defined for any sharded array; `Array.info` and
  `Array.nchunks_initialized` work for rectilinear shard grids instead of
  raising (`info` shows the shard shape as `<variable>`).
- Zero-length axes: `chunks=-1` and `chunks=False` resolve to chunk size 1
  (#4307, #4328) instead of ZeroDivisionError / invalid metadata. (#4334, still
  open at time of writing, would finish this by making it one invariant; only
  mention it if it lands first.)
-->

## Errors that tell you what to install

<!--
SMALL WIN, one paragraph. #4277. Opening an array whose codec has no
registered implementation used to raise a bare KeyError; now
`zarr.errors.UnknownCodecError` (exported from zarr.errors) with the package
to install. Show the message verbatim:

    An implementation for codec 'wavpack' is not available. Register one
    explicitly using the codec registry (see ...), or install a Python package
    that registers a codec implementation with numcodecs. Known packages
    supporting this codec: wavpack-numcodecs.

The lookup tables live in src/zarr/registry.py (one per Zarr format) and
include the codecs numcodecs gates behind its own extras (zfpy, pcodec,
crc32c, msgpack2); codec authors are invited to add their package.
BEHAVIOUR CHANGE to flag: `except KeyError` no longer catches these (they are
ValueError subclasses; `except ValueError` still works).
-->

## `UPath` works wherever a store does

<!--
SMALL WIN, one paragraph. #4265. `UPath("s3://bucket/data.zarr")` now creates
an FsspecStore carrying the UPath's filesystem and storage options; a local
UPath creates a LocalStore, so UPath('/data') and Path('/data') behave the
same. This had only worked by accident and stopped working with
universal-pathlib >= 0.3. `FsspecStore.from_upath` also converts sync
filesystems to async mode instead of raising.
-->

## Robustness

<!--
OPTIONAL PARAGRAPH (a good story: property testing paid off). A cluster of
long-standing bugs closed this release:

- orthogonal writes on sharded arrays with two or more array-indexed axes
  (#4284, #4316) -- the nightly Hypothesis run caught it; a new public
  `zarr.testing.strategies.sharded_arrays` strategy (with one level of nested
  sharding) gives the sharded write path real weight in the property tests
  (#4331). Downstream projects can use it too.
- unsigned index arrays (#4286, #4332): uint8/uint16 unsorted selections raised
  IndexError; uint64 promoted to float; and a uint64 above intp max could wrap
  to a valid negative index and read the wrong element -- now bounds-checked
  before narrowing. Index arrays passed by the caller are no longer mutated.
- consolidated metadata no longer depends on the on-disk key order (#4227) --
  sibling groups whose names differ only by case became unreachable.
- fsspec filesystems whose storage options are not JSON-serialisable
  (e.g. azure.identity credentials) no longer fail in FsspecStore.from_url /
  from_mapper (#4239).
- `from_array` now keeps the source's fill value, attributes (deep-copied) and
  exact Zarr data type (#4288, #4325, #4335) -- variable-length bytes arrays
  can be copied.
- `Group.require_array` accepts a ZDType (#4189); numpy integers and numpy
  arrays are accepted as chunk/shard specs (#4257, #4329).
-->

## Things to be aware of

<!--
MUST-MENTION list; keep it short and factual.

- NEW REQUIRED DEPENDENCY: `msgspec>=0.19`, for metadata validation (#4063).
  Packagers: the conda-forge recipe needs it added. Parsing is stricter: a
  float `"zarr_format": 2.0` and booleans where ints are expected are now
  rejected; spec-conforming metadata is unaffected. (The attribute
  nesting-depth limit that #4063 introduced was removed again before release,
  #4330 -- no need to mention unless someone tested a pre-release.)
- Exception types for unknown codecs changed (see above): KeyError ->
  UnknownCodecError / BadConfigError (ValueError subclasses).
- Nested-sequence chunk specs require the rectilinear flag again (see above).
- `from_array` behaviour change: copies fill value / attributes / dtype from a
  Zarr source (a fix, but visible). Explicit `fill_value=None` now means the
  dtype default, consistent with create_array.
- `cast-value-rs>=0.4.2` is required for the `cast_value` codec; older
  versions silently corrupted non-row-major input (#4260). Enforced at runtime
  too, so an old install now raises ImportError instead of corrupting data.
- A `scale_offset` codec with a string-valued zero scale ("0", "0.0", hex) is
  now rejected (#4279); such arrays read back all-NaN before.
- The sdist now ships only `src`, `tests`, `docs`, `examples` and the mkdocs
  files (allowlist, #4261) -- no more subpackages inside the zarr sdist.
-->
