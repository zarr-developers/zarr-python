`parse_named_config_json` now rejects `"must_understand": false`. The Zarr v3
spec does not support it for chunk key encodings — a reader that does not
recognize one cannot skip the array, it has to fail — so a document carrying
it is malformed rather than merely redundant. `true` is still accepted as an
explicit spelling of the default.

Unexpected metadata keys of mixed types no longer raise a bare `TypeError`
while building the error message, which escaped the package's error
hierarchy; they are reported as a `ChunkKeyConfigurationError` like any other
unexpected key.
