A v2 array document that omits `dimension_separator` is now written back
without it: `to_json` and `to_key_value` no longer add
`"dimension_separator": "."`. The model's `dimension_separator` is still
`"."`, and the model still compares equal to one whose document writes
`"."`. Removing the key with `update(dimension_separator=UNSET)` now takes
effect in the written document.

v2 consolidated metadata no longer rejects nodes whose names only Zarr v3
reserves. A `.zmetadata` with a node named `__private` or `zarr.json` was
reported as invalid, because the v2 reader checked node paths with the v3
naming rules. Zarr v2 reserves no node names.

The v2 array types now declare that `shape` and `chunks` hold non-negative
integers, as the v2 validator already required, so `check` and
`json_schema` reject a negative length too. The v3 `zarr.json` JSON Schema
now requires at least one codec, as the validator does.
