A v2 array document that omits `dimension_separator` is now written back
without it: `to_json` and `to_key_value` no longer add
`"dimension_separator": "."`. The model's `dimension_separator` is still
`"."`, and the model still compares equal to one whose document writes
`"."`. Removing the key with `update(dimension_separator=UNSET)` now takes
effect in the written document.

`to_json`, `to_key_value` and `create_default` write a field as it was
read. They no longer shorten a codec, chunk grid or chunk key encoding
to its bare name, such as `"crc32c"`. A Zarr v3.0 reader, zarr-python
included, does not accept a bare name in `codecs`, so zarr-python could
fail to open a document that 0.5.0 wrote.

Readers, model constructors and `from_key_value` no longer raise `RecursionError`
on a deeply nested document. Nesting is capped at 256 levels, and a
deeper value is an `invalid_value` problem at the level past the limit.
