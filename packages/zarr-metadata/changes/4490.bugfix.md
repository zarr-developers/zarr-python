`to_json` and `to_key_value` write every extension point but a data
type as an object, `{"name": "crc32c"}`, where they wrote the bare name
for a field with nothing to configure. A Zarr v3.0 reader takes no
short-hand name in `codecs`, and no zarr-python release reads one there
or in `chunk_key_encoding`, so a document the package wrote could not be
opened by them. A data type with nothing to configure is still written
by its bare name.
