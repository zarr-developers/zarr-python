Compared with 0.5.0, some names are removed and some are exported from a
different module. Every public name is now exported by exactly one module.
The top-level `zarr_metadata` namespace still exports the common names,
so code that imports from `zarr_metadata` is affected only by the
removals.

Removed from `zarr_metadata.model`:

- the key sets `ARRAY_METADATA_REQUIRED_KEYS_V3`,
  `ARRAY_METADATA_OPTIONAL_KEYS_V3`, `ARRAY_METADATA_STANDARD_KEYS_V3`,
  `ARRAY_METADATA_REQUIRED_KEYS_V2`, `GROUP_METADATA_REQUIRED_KEYS_V3`,
  `GROUP_METADATA_OPTIONAL_KEYS_V3`, `GROUP_METADATA_STANDARD_KEYS_V3` and
  `GROUP_METADATA_REQUIRED_KEYS_V2`; read the keys of a document type from
  its TypedDict, for example `ZarrV3ArrayMetadataJSON.__required_keys__`;
- `is_json`, `validate_json` and `parse_json`, with no replacement.

Exported from a different module:

- `ValidationProblem`, `ProblemKind` and `MetadataValidationError` move
  from `zarr_metadata.model` to the new `zarr_metadata.problems`.
- The store keys and store-key types (`ZARR_V3_ARRAY_METADATA_STORE_KEY`,
  `ZarrV3ArrayMetadataStoreKey`, and the rest) are no longer exported
  from `zarr_metadata.model`; import them from the `v2` or `v3` module for
  their document, such as `zarr_metadata.v3.array`.
- The document TypedDicts are no longer exported from `zarr_metadata.v2`
  or `zarr_metadata.v3`; import them from `zarr_metadata.v2.array`,
  `zarr_metadata.v3.group` and so on. The same holds for
  `ZarrV2ArrayDimensionSeparator` and `ZarrV2ArrayOrder` (now in
  `zarr_metadata.v2.array`), `ZarrV2CodecMetadata` (now in
  `zarr_metadata.v2.codec`) and `ZarrV2DataTypeMetadata` (now in
  `zarr_metadata.v2.data_type`).
- The `codec`, `data_type`, `chunk_grid` and `chunk_key_encoding`
  packages no longer re-export their submodules' names; import each from
  its submodule, for example
  `from zarr_metadata.v3.data_type.float32 import Float32FillValue`.
- `ZarrV2DataTypeMetadata` moves from `zarr_metadata.v2.array` to
  `zarr_metadata.v2.data_type`.
- `NUMPY_TIME_UNIT` moves from `zarr_metadata.v3.data_type.numpy_timedelta64`
  to `zarr_metadata.v3.data_type.numpy_datetime64`. `NumpyTimeUnit` is no
  longer exported from `numpy_timedelta64`; import it from
  `numpy_datetime64`.

The pydantic field types are renamed `ZarrV3ArrayMetadataField`,
`ZarrV3GroupMetadataField`, `ZarrV3ConsolidatedMetadataField` and their
`ZarrV2` twins, so they no longer share names with the model classes,
which are different objects.
