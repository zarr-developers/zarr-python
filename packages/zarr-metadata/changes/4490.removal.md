The parts of field reading that Zarr v2 and v3 share now have one public
home, `zarr_metadata.definition`: `Definition`, `WithFillValue`,
`EmptyConfiguration`, `Nested`, `Loc`, `resolve`, `AcceptedField`,
`UnclaimedField`, `RefusedField`, `ResolvedField`, `Context`, `ClaimKey`,
`Claims`, `Conflict`, `Disagreements`, `ScopeConflictError`,
`canonical_of`, `canonical_fill_value`, `fill_value_problems` and
`with_problems`. They are no longer exported from
`zarr_metadata.v3.definition` or `zarr_metadata.v2.definition`, which now
hold only each format's own kinds and scopes. `JSONValue`,
`MetadataValidationError`, `ProblemKind`, `ValidationProblem` and `shown`
are no longer exported from `zarr_metadata.v3.definition`; import the
first four from `zarr_metadata`.

JSON Schema output also has one home, `zarr_metadata.json_schema`:
`json_schema` and `JSONSchema` move there from `zarr_metadata.typed_json`,
and `node_metadata_json_schema_v3` from `zarr_metadata.model`.
`field_json_schema`, which was documented but not exported, is exported
there too.
