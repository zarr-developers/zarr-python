The parts of field reading that Zarr v2 and v3 share now have one public
home, `zarr_metadata.definition`: `Definition`, `WithFillValue`,
`EmptyConfiguration`, `Nested`, `Loc`, `resolve`, `AcceptedField`,
`UnclaimedField`, `RefusedField`, `ResolvedField`, `Context`, `ClaimKey`,
`Claims`, `Conflict`, `Disagreements`, `ScopeConflictError`,
`canonical_of`, `canonical_fill_value`, `fill_value_problems` and
`with_problems`. They are no longer exported from
`zarr_metadata.v3.definition` or `zarr_metadata.v2.definition`, which now
hold only each format's own kinds and scopes. `JSONValue`,
`MetadataValidationError`, `ProblemKind`, `ValidationProblem` and `shown`
are no longer exported from `zarr_metadata.v3.definition`; import the
first four from `zarr_metadata`.

JSON Schema output also has one home, `zarr_metadata.json_schema`:
`json_schema` and `JSONSchema` move there from `zarr_metadata.typed_json`,
and `node_metadata_json_schema_v3` from `zarr_metadata.model`.
`field_json_schema`, which was documented but not exported, is exported
there too.

The `codec`, `data_type`, `chunk_grid` and `chunk_key_encoding` packages
no longer re-export the names of their submodules. Import each codec's,
data type's, chunk grid's or chunk key encoding's types and definition
from its own submodule, for example
`from zarr_metadata.v3.data_type.float32 import Float32FillValue`.
`zarr_metadata.v2.codec` keeps `V2_CODECS` and `ZarrV2CodecMetadata`,
and `zarr_metadata.v2.data_type` keeps `V2_DATA_TYPES`; these two are no
longer exported from `zarr_metadata.v2.definition`.

Every public name is now exported by exactly one module. The top-level
`zarr_metadata` namespace still exports the common v3 names as a
convenience. Names that are no longer exported from a second module:

- the store keys and store-key types: import them from the `v2` or `v3`
  module for their document (`zarr_metadata.v3.array`, ...), not from
  `zarr_metadata.model`;
- the document `TypedDict`s: import them from `zarr_metadata.v2.array`,
  `zarr_metadata.v3.group` and so on, not from `zarr_metadata.v2` or
  `zarr_metadata.v3`;
- `ValidationProblem` and `ProblemKind`: import them from
  `zarr_metadata.model` (or `zarr_metadata`), not from
  `zarr_metadata.typed_json`;
- `Loc`: import it from `zarr_metadata.typed_json`, not from
  `zarr_metadata.definition`;
- `NumpyTimeUnit`: import it from
  `zarr_metadata.v3.data_type.numpy_datetime64`.

Two names that meant different things in different modules are renamed:
the pydantic field types are now `ZarrV3ArrayMetadataField`,
`ZarrV3GroupMetadataField`, `ZarrV3ConsolidatedMetadataField` and their
`ZarrV2` twins, so they no longer share names with the model classes; and
the v2 blosc compressor type is now `ZarrV2BloscCName`, so it no longer
shares a name with the v3 `BloscCName`.
