`v3/_typed_json` is the type checker the definition layer reads
metadata with, on its own: for each shape JSON takes -- `int`, `float`,
`bool`, `str`, `None`, `JSONValue`, a `Literal`, `tuple[T, ...]` and
`tuple[T1, T2]`, a union, a TypedDict, `Mapping[str, V]`, a `NewType`
and a type alias -- a parser compiled once from the annotation. A
parser is a pure function, `(value, loc) -> (typed value, problems)`,
and a caller's leaf is asked first at every depth for shapes of its
own. A TypedDict is read as the typing spec defines it: `typeddict_keys`
takes each key's `Required` or `NotRequired` from the evaluated
annotations, so a module written with `from __future__ import
annotations` reads like any other, falls back on the declaring class's
`total`, and takes `closed` and `extra_items` from the class or, when it
says neither, from its bases. What comes back is a value of the type: a
key a closed TypedDict does not declare is reported and left out. The
module knows nothing of metadata fields.
