**Breaking:** `read_node_metadata_v2`, `read_repaired_node_metadata_v2`
    and the v2 models' `from_key_value` locate each problem in the file that
    holds it, `(".zarray", "order")` or `(".zattrs", "x")`, as
    `read_consolidated_metadata_v2` locates it in its entry. They located
    problems in the merged document, so a `.zarray` that wrote `attributes`
    beside a `.zattrs` that was not an object gave two problems at
    `("attributes",)`, a location in neither file. An array node's reading
    locates its fields there too: its new `at` is `(".zarray",)`, so
    `fields()` gives `(".zarray", "dtype")` and `with_problems` pairs each
    field with its problems. Its model reads the merged document, so the
    model's own `reading` locates the field at `("dtype",)`, and no longer
    equals the node reading.
