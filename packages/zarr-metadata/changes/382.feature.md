An extension is named as the spec names one -- `^[a-z][a-z0-9-_.]+$`, or
a URI, which earlier versions of the spec required, in the characters
RFC 3986 writes one in -- and any other name, `""` or `"foo/bar"`, is
refused before a definition is asked, an `invalid_value` at `name`,
where every string read as an unknown extension. `well_named` says so of
a string, `validate_metadata_field_v3` refuses it as the envelope rule it
is, the JSON Schema's unclaimed branch carries the same pattern,
and a definition given another name is a `TypeError` when it is built,
since no field could name it.
