The README says what the core depends on, `typing-extensions` and
`annotated-types` only, and why it has no validation framework: a pin
would collide with consumers' pins. The validation boundary says what
the package decides where the specs leave it open: `attributes` may
hold `NaN` and `Infinity`, which `to_key_value` writes as bare tokens.
The models' `from_json`, `to_json`, `from_key_value` and `to_key_value`
have docstrings, and no public docstring names a private function.
