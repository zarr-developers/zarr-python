A v2 typestr with a part its family does not take, such as `<f4[ns]` or
    `|O4`, is refused with one `invalid_value` problem that names the part:
    "expected a name 'float' reads, got "<f4[ns]", which encodes a unit that
    it does not take". It was refused as one `unknown_key` problem per
    internal configuration key (`unit`, `scale_factor`, `itemsize`), a kind
    a caller who tolerates unknown keys leaves out, so such a caller read the
    typestr as valid. A time typestr without a unit, `<M8`, is an
    `invalid_value` too, not a `missing_key`.
