`read_repaired_node_metadata_v2` reads a v2 node from its decoded files
after it undoes a known writer bug: zarr-python 3.0.0 to 3.0.6 wrote a
non-finite fill value of a float or complex array as a bare `NaN`,
`Infinity` or `-Infinity`, which is not JSON, so the strict read refuses
it. The repair writes each one as the string the v2 spec uses, such as
`"NaN"`. `repair_node_metadata_v2` applies the repair without reading the
result. `read_repaired_consolidated_metadata_v2` and
`repair_consolidated_metadata_v2` apply it to each `.zarray` entry of a
`.zmetadata` too. `read_repaired_node_metadata_v3` repairs the same bug
in the documents a v3 group's consolidated metadata lists, where those
versions wrote it for float64 arrays.
