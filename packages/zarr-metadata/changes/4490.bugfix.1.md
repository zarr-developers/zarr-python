A v2 structured dtype with a `U` field now accepts the fill values that
zarr-python 2.18 and 3.x write. A `U` size counts code points of four
bytes each, so a record of `[["s", "<U3"], ["v", "|b1"]]` takes 13 bytes,
not 4, also inside a nested struct. A fill value of the wrong size, which
was accepted before, is now a problem.
