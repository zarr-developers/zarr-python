A member a closed object does not declare is an `unknown_key` wherever
it sits, as `ProblemKind` defines one: in a v2 `.zgroup`, a `.zmetadata`
envelope, a group's `consolidated_metadata` and a metadata field's
envelope, where it was an `invalid_value`, as it already was inside a v3
configuration. So a reader that tolerates a key another writer added,
such as netCDF-C's `_nczarr_*` keys in a `.zgroup`, can filter by kind.
A definition's `check` and `judge` give a configuration back when a
field it holds has a stray member, which they report and leave out, as
the checker does a key a closed TypedDict does not declare.
