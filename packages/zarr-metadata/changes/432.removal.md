Rename the package's vocabulary to match zarrs: a name/value pair in a JSON metadata object is now a *field* (it was a *member*; the v3 spec uses both words for this, zarrs uses only *field*), and a value at an extension point that a context resolves is now a *declaration* (it was a *field*). The public names change with no aliases:

- `AcceptedField`, `UnclaimedField`, `RefusedField` and `ResolvedField` are now `AcceptedDeclaration`, `UnclaimedDeclaration`, `RefusedDeclaration` and `ResolvedDeclaration`.
- `ZarrV3DataTypeField`, `ZarrV3ChunkGridField`, `ZarrV3ChunkKeyEncodingField`, `ZarrV3CodecField`, `ZarrV3StaticCodecField`, `ZarrV3StorageTransformerField` and `ZarrV2DataTypeField` are now the same names ending in `Declaration`, and a kind's `field_aliases` is now `declaration_aliases`.
- `ZarrV3MetadataFieldJSON` is now `ZarrV3DeclarationJSON`, and `field_json_schema_v3` is now `declaration_json_schema_v3`.
- A reading's `fields()` is now `declarations()`, and a model's `unclaimed_fields` is now `unclaimed_declarations`.
- The first parameter of `with_problems` is now `declarations` (it was `fields`), and the first parameter of `ZarrV3ConsolidatedMetadata` is now `value` (it was `member`).
- `ExtraFieldDefinition.spec_members` (and so `ArrayExtraFieldDefinition.spec_members` and `GroupExtraFieldDefinition.spec_members`) is now `spec_fields`.
- The JSON Schemas that `node_metadata_json_schema_v3` and `declaration_json_schema_v3` write name each alias under `$defs` by its new name, so a `$ref` to `#/$defs/ZarrV3CodecField` is now `#/$defs/ZarrV3CodecDeclaration`, and likewise for the other kinds.

Messages that said *member* now say *field*, and messages that said *field* or *metadata field* for an extension-point value now say *declaration*, as in "expected a declaration (string or extension object)". `extra_fields`, `ExtraFieldDefinition`, `ZarrV3ExtensionField`, `StructField` and the pydantic `...MetadataField` types keep their names.
