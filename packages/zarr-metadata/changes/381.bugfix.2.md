A group's consolidated metadata is judged as the hierarchy below the
group, the group its root: zarr-python keeps the document of the node at
`/a/b` at the key `a/b`, and the documents and the group make a tree in
which only groups hold nodes and each node's parent is held. A key that
is no node's path below the group, such as `""`, `"__a"` or `"a/../b"`,
and a document below an array's were read without a problem, and so was
a document whose group is missing, which zarr-python fails to read. Each
is a problem now, a missing group a `missing_key`, and
`ZarrV3ConsolidatedMetadata` refuses them when it is built.
