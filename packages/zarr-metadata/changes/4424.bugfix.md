A v2 array document's members outside the `.zarray` definition are still
tolerated, and dropped on read, but one that is not a JSON value, or whose
key is not a string, is now a problem, as it is in a v3 document.
`parse_array_metadata_v2` returned such members in a document its type
says holds string keys, which `is_array_metadata_v2` refused.
`ZarrV2ArrayMetadataJSON` declares its other members as JSON values
(`extra_items`), as its pydantic schema already did.
