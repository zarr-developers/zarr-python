Absent members are now `UNSET` instead of `None`, so they can be told apart from a JSON `null`: a reading's `data_type`, `chunk_grid` and `chunk_key_encoding` when the key is missing, and `Refused.json` when the field was not JSON. A metadata field with no `name` is a `missing_key` problem instead of `invalid_type`. `ZarrV3ConsolidatedMetadata` declares `must_understand` as `False` instead of accepting and then refusing a value.
