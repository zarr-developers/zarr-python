The v2 models are now a document and the scope it was read in, as the v3 models are: `ZarrV2ArrayMetadata(document, context=None)` reads the document in `CORE_V2` or the scope given, holds `dtype`, `compressor` and each filter as the scope read them, and compares by what the document means, so `<b1` and `|b1`, or a fill value written `0` and `0.0` for a float, are one array. `update` reads new members in the model's own scope; `with_context` and `refined_in` read the document in another; `refines` orders models by information. `ZarrV2ConsolidatedMetadata` keeps its entries as written and adds `nodes`, each `.zarray` or `.zgroup` entry with its `.zattrs` as a model; a problem in an entry is reported under that entry. `read_array_metadata_v2` reads a document once and returns everything it found. Every v2 reader takes a scope; the v2 pydantic field types read in the scope under the validation context's `zarr_metadata_context_v2` key, or in a bare `Context` given as the context, which every field type reads in. zarr-python 3.x writes a `consolidated_metadata` member into each `.zgroup` entry below the root of a v2 `.zmetadata`, which the strict read refuses; `read_repaired_consolidated_metadata_v2` removes it and reads the repaired document, and `repair_consolidated_metadata_v2` says what was changed. A member of a `.zarray` the spec does not define is now kept and written back.
