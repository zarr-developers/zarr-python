**Breaking:** `create_default` derives each member that depends on a member given, unless that member is given too. In v3, a `data_type` brings its default fill value and an array -> bytes codec: `vlen-utf8` for `string`, `vlen-bytes` for `bytes` and `variable_length_bytes`, and `bytes` for any other data type. So `ZarrV3ArrayMetadata.create_default(data_type="bool")` and `create_default(data_type="string")` now work. In v2, a `dtype` brings its default fill value instead of `null` when `0` does not fit: `false` for `|b1`, `""` for `|S` and `<U`, and null bytes for `|V` and structs. `|O`, whose values may be of any type, has no default and gets `null` where it got `0`. A v3 data type that nothing in scope claims needs a `fill_value`. When the document has a problem, the error notes each member `create_default` filled in. The default fill values come from a new `fill_value_default` on a data type definition, which every data type this package defines declares, with zarr-python's defaults: zero, `false`, the empty string, null bytes, and `NaT` for times. `zarr_metadata.definition` exports `ConstantFillValue`, for a default that does not depend on the configuration, and `default_fill_value(data_type)`.
