`FsspecStore.from_url` now creates its filesystem with
``skip_instance_cache=True``, so the filesystem it creates is owned by the
store and is released when the store is released, instead of being retained
in fsspec's global instance cache until interpreter shutdown. This prevents
backends that register shutdown finalizers (e.g. ``adlfs``) from emitting
``RuntimeError: Loop is not running`` noise on every process exit. Pass
``skip_instance_cache`` in ``storage_options`` to restore the previous
instance-sharing behavior.
