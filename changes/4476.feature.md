Added the builtin `zarr:`, `zarr2:` and `zarr3:` URL pipeline adapters, so a pipeline
can address a Zarr node within a resource and select its format, e.g.
`zarr.open_group("file:///data/archive|zarr2:path/to/group")`. The text after the colon
is a path within the preceding resource; `zarr2:` / `zarr3:` select the Zarr format and
`zarr:` auto-detects it. These schemes are adapter-only, so strings without `|` behave as
before.

`Group.open`, `Array.open`, `AsyncGroup.open` and `AsyncArray.open` no longer default to
`zarr_format=3` when given a URL pipeline: if `zarr_format` is not passed, the pipeline's
format segment decides (auto-detection when there is none). For every other store the
default is still 3.
