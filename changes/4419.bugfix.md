`zarr.array` now accepts the same keyword arguments for a zarr array as for any other data, as its documentation says. Previously a zarr array was passed to `from_array`, so `zarr.array(zarr_array)` raised for a missing `store`, and `create` arguments such as `mode` or `dtype` raised `TypeError`. The new array takes its shape, dtype and chunks from the source by default, and the data is still copied one region at a time. The source's codecs, fill value and attributes are no longer copied; use `zarr.from_array` for that.
