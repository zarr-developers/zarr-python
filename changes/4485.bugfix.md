Validate consolidated metadata listings at parse time. In v3 listings,
keys containing a reserved node name (`.`, `..`, `zarr.json`, or a
`__`-prefixed segment) now emit a `ZarrDeprecationWarning` instead of
being accepted silently; stores written before these names were rejected
still open. Keys with empty path segments still raise
`MetadataValidationError`, as do listings whose parent group entry is
missing or that place a node below an array; those cases previously
surfaced as `KeyError` or left the group unopenable. The reserved-name
check does not apply to v2 listings, whose specification does not
reserve node names.
