Added core support for URL pipelines (https://github.com/jbms/url-pipeline):
`|`-chained URLs that address zarr data through nested storage layers, e.g.
`s3://bucket/data.zip|zip:|zarr3:`. A parsed `zarr.storage.URLPipeline` (built with
`URLPipeline.from_url`) can be passed to any function that accepts a `StoreLike`,
including `zarr.open`, `zarr.open_group`, `zarr.open_array` and
`zarr.open_consolidated`. Adapters for the
sub-URLs after the first are provided by third-party packages (e.g. Icechunk) through
the `zarr.url_adapters` entry-point group and the single-method
`zarr.abc.url_pipeline.URLPipelineAdapter` interface, which receives a
`zarr.storage.PipelineSegment` and `zarr.storage.PipelineContext` and returns a
`zarr.storage.StorePath`; adapters are loaded lazily and individually, and
`zarr.registry.register_url_adapter` registers one without an entry point. A builtin
`zip:` adapter will follow separately.

Behavior notes:

- Plain strings are never interpreted as pipelines: `zarr.open("data|x.zarr")` still
  addresses a local directory of that name, whatever adapters are installed. Only
  `URLPipeline.from_url` reads a string as a pipeline.
- `URLPipeline.from_url` raises `TypeError` for anything but a `str`, and
  `URLPipelineError` for a string it cannot parse: an empty sub-URL, a root without a
  URL scheme (including a bare local or Windows drive path), an invalid adapter scheme,
  a fragment, an ASCII control character, or whitespace at either end of a sub-URL.
- A trailing `zarr2:`/`zarr3:` segment selects the zarr format of the open or create
  call, and its body is the path of the node to open. A `zarr_format` argument that
  conflicts with it raises `ValueError`, including the default of 3 in
  `zarr.create_array`, `Group.from_store`, `Group.open` and `Array.open`: pass the
  matching format (or `zarr_format=None` where it is accepted) to open a `zarr2:`
  pipeline with these.
- Inside a pipeline, `memory:` and `file:` roots follow the URL pipeline spec's spelling
  rules (`memory:` ≡ `memory:/` ≡ `memory://`; `file:` must carry an absolute path with
  at most a `localhost` authority). Percent-escapes are not decoded, matching
  `LocalStore`. A pipeline's `memory:` root is zarr's `ManagedMemoryStore`, which does
  not share data with the fsspec in-memory filesystem a plain `memory://name` string
  resolves to.
- Wrapper adapters can open a local *file* root only in mode `"r"` (via
  `dataclasses.replace(context, mode="r").resolve_preceding()`); writing through a
  container file is not yet supported.
- A `zarr.url_adapters` entry point whose scheme is already registered is ignored with a
  `ZarrUserWarning`, as are duplicate entry-point names; an entry point that fails to
  import raises `URLPipelineError` naming it, and stays discoverable for a retry.
