Added the `NCZarrChar` data type for the netCDF `NC_CHAR` type as NCZarr writes it in Zarr format 2 (`>S1`). Arrays with this data type keep the `>S1` spelling when their metadata is written back, so netCDF readers still see characters rather than strings. Zarr format 2 fixed-length bytes written with a `<` or `>` byte order (e.g. `<S3`, as written by Zarr.jl) can be read again.
