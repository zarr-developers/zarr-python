`DateTime64` and `TimeDelta64` now reject the `generic` unit combined with a `scale_factor` other than 1, and store the `μs` unit under NumPy's `us` spelling. Previously both values were accepted but did not survive a round trip: NumPy has no scale for the generic unit, so `DateTime64(unit="generic", scale_factor=2).to_native_dtype()` silently became plain `datetime64` (and the Zarr V2 dtype string dropped the scale factor while the V3 metadata kept it), and `DateTime64(unit="μs")` came back from NumPy as `DateTime64(unit="us")`, which compared unequal to the original. Metadata that spells the unit `μs` still reads correctly.
