`DateTime64` and `TimeDelta64` now reject the `generic` unit with a `scale_factor` other than 1, and normalize `μs` to `us`. NumPy retains a generic scale internally, but its `dtype.str` omits that scale, so the Zarr V2 dtype-string round trip loses it. The generic-scale rejection is an implementation policy, not an explicit constraint in the V3 temporal extension specification. The equivalent microsecond spellings remain readable and serialize as `us`.
