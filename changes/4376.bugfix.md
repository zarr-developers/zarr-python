Chunk specifications are judged only by the chunk normalizer: the separate duck-typed check for rectilinear input is gone, so the Zarr format 2 and sharding restrictions apply to what the normalized grid says was declared. A chunk size is an integer by Python's integer protocol: numpy integer scalars and 0-d integer arrays are accepted wherever a chunk or shard shape is, and a `bool` inside a chunk specification (e.g. `chunks=(True, 5)`) is rejected instead of being read as a chunk size of 1. The legacy `zarr.create(..., zarr_format=2)` no longer tests the truth value of `chunks`, so numpy arrays work there, and `chunks=0` and `chunks=[]` now raise a `ValueError` instead of silently falling back to automatic chunking. A non-integer scalar chunk specification raises a `TypeError` naming the problem.
