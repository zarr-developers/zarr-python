A structured data type now resolves its field data types with the data type registry that resolves it, instead of always using the default registry. `get_data_type_from_json`, `get_data_type_from_native_dtype`, `parse_dtype`, `parse_data_type`, `Structured.from_json` and `Struct.from_json` take an optional `registry`. A structured data type with a field whose data type matches no data type now raises `zarr.errors.NestedDataTypeValidationError` naming the path to that field (e.g. `at path ['outer', 'y']`), instead of reporting that the whole structured data type matches nothing. Data types registered through the `zarr.data_type` entry point group are now loaded; previously they were collected but never registered.
