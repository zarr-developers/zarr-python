Added `zarr.registry.Context`, the extensions that Zarr metadata is read with; for now it holds the data type registry. A structured data type now resolves its field data types from the context it is read in, instead of always from the default registry. `get_data_type_from_json`, `get_data_type_from_native_dtype`, `parse_dtype`, `parse_data_type`, `Structured.from_json` and `Struct.from_json` take an optional `context` (default: `Context.default()`). A structured data type with a field whose data type matches no data type now raises `zarr.errors.NestedDataTypeValidationError` with the JSON Pointer of that field (e.g. `at /configuration/fields/1/data_type`), instead of reporting that the whole structured data type matches nothing. Data types registered through the `zarr.data_type` entry point group are now loaded; previously they were collected but never registered.
