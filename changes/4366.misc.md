`zarr.open`, `open_array`, `open_group`, `AsyncArray.open` and `AsyncGroup.open` are now built on one metadata reader, `zarr.core.group.read_node_metadata`, composed of per-format readers (`read_v3_metadata`, and for format 2 a reader per kind, `read_v2_array_metadata` and `read_v2_group_metadata`, plus `read_v2_metadata` for when the kind is unknown); with `zarr_format=None` format 3 is tried first and the format 2 documents are read only when there is no `zarr.json`. An opener that knows which kind it wants reads only that kind's documents: `open_array` on a format 2 array reads `.zarray` and `.zattrs` and nothing else. Opening a Zarr format 3 node costs a single read where `zarr.open` used to make up to seven. `zarr.open` now has a stated contract: with `shape` it behaves as `open_array`; otherwise the reading modes open whatever node is there ('a' creating a group when there is none) and the creating modes create a group ('w' replacing whatever is there). Consequences: `zarr.open(shape=...)` on a Zarr format 3 group raises `ContainsGroupError` instead of `TypeError`; `zarr.open(mode="w-")` without `shape` creates a group instead of raising; `zarr.open` applies `config` to an array and ignores it for a group; `zarr.open(mode="r")` on nothing raises `NodeNotFoundError`; opening a Zarr format 3 array as a group raises `ContainsArrayError` and a format 3 group as an array `ContainsGroupError` (a format 2 node of the other kind is not looked for and reads as missing in the read modes); a Zarr format 3 document whose `node_type` is missing or unknown raises `NodeTypeValidationError` everywhere; and a path holding both formats is read as format 3 without a warning. `WrapperStore` now forwards `supports_consolidated_metadata` to the store it wraps, where it used to answer `True` for any wrapped store. The Zarr format 2 consolidated-metadata key is `.zmetadata` and not configurable: `use_consolidated` is a bool or None, and the never-tested option of passing a custom key as a string is gone. `zarr.errors.NodeNotFoundError`, the shared base of `ArrayNotFoundError` and `GroupNotFoundError` and now what `zarr.open` raises when there is no node, is exported from `zarr.errors` and appears in the error documentation.
